## OpenClaw 是什么？

**OpenClaw（常被戏称为“养龙虾”）** 是一个开源的个人 AI 助手 / Agent 平台，可以长期运行在你的电脑或服务器上，帮助你：

- 统一管理 **多个大模型提供方**（OpenAI、Claude、国内云厂商、本地模型等）
- 像“小秘书”一样执行任务：读写文件、调用接口、自动化脚本
- 记住你的偏好和历史对话，形成“长期记忆”

可以把它理解为：**一个“AI 操作系统内核”**，上面可以挂各种前端（Web 面板、命令行、Bot 等），后面可以接各种模型（云端 + 本地）。

---

## OpenClaw 适合谁用？

更适合这些场景：

- 你已经在用 Cursor、Claude Code，但希望有一个 **长期运行、可自动化的 AI 中枢**
- 你想 **在本地跑模型**，减少成本和隐私风险，同时又不想放弃云端大模型的能力
- 你想做一些 **“长流程”任务**：例如看 Git 仓库、自动整理文档、跑脚本、定期汇总信息等

如果你只是偶尔问几个问题，用 Cursor、Claude、ChatGPT 就够了；OpenClaw 更偏向“重度玩家”和“想搭个人 AI 基础设施”的用户。

## 架构快速理解：云模型 vs 本地模型

用一个极简思路来看 OpenClaw：

- **入口层（Gateway）**：接受你的请求（Web、CLI、Bot 等）
- **模型层（Models）**：决定用哪个模型来回答（云端 / 本地 / 混合）
- **记忆与工具层（Memory & Tools）**：负责长期记忆、调用外部工具/脚本

在模型层，大致有三种玩法：

- **纯云端模式**：只用 OpenAI、Claude 等云模型
- **纯本地模式**：只用本地 LLM（Ollama / LM Studio 等）
- **混合模式（推荐）**：本地模型负责日常对话、简单任务；云模型在需要时兜底

你这台机器（Windows + GTX 1060）更适合 **“轻量本地 + 适量云端”** 的组合。

## 在 Windows 上安装 OpenClaw

下面假设你使用的是 **Windows 10/11 64 位**，并且习惯用 PowerShell。

### 1. 系统与环境准备

- Windows 10 / 11（64 位）
- 建议 **16GB 以上内存**（本地模型越大越吃内存）
- 至少预留 30GB 以上磁盘空间
- 建议先安装：
  - [Node.js](https://nodejs.org/) 18+（若使用 npm 安装）
  - Git（可选，但后续管理配置文件、脚本很方便）
- 建议在 PowerShell 中放宽当前用户的执行策略（否则有时脚本会被拦截）：

```powershell
Get-ExecutionPolicy

# 如果上面的结果是 Restricted，可以执行：
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

### 2. 推荐：一键脚本安装

在 **PowerShell（建议以管理员身份打开）** 中执行：

```powershell
iwr -useb https://openclaw.ai/install.ps1 | iex
```

脚本会帮你：

- 安装 OpenClaw CLI
- 安装后台服务（daemon）
- 提示你运行引导命令

安装结束后，按照提示执行：

```powershell
openclaw onboard
openclaw dashboard
```

- `openclaw onboard`：引导你完成基础配置（账户、模型、存储位置等）
- `openclaw dashboard`：打开 Web 控制台，方便你在浏览器里操作

### 3. 可选：npm 安装方式

如果你已经正确安装了 Node.js，也可以这样：

```powershell
npm install -g openclaw@latest
openclaw onboard --install-daemon
```

完成后同样可以使用：

```powershell
openclaw doctor      # 自检环境
openclaw dashboard   # 打开管理面板
```

**建议**：如果对 Node 不熟，直接用官方 PowerShell 脚本安装即可。

## 在 Windows + GTX 1060 上跑本地模型

你的显卡是 **GTX 1060（6GB 显存）**，现实情况大致是：

- 适合：**7B 级别、4bit 量化** 的模型（例如 Qwen/DeepSeek 这类 7B 版本）
- 不适合：70B、34B 这类超大模型——即使勉强跑起来也很慢、很容易 OOM
- 建议系统内存：至少 16GB，越多越好

比较现实、稳定的一条路线是：**Ollama + 7B 模型 + OpenClaw 对接**。

### 1. 安装 Ollama for Windows

1. 打开浏览器访问 `https://ollama.com/`（国内网络可能需要加速）
2. 下载 Windows 安装包并安装
3. 安装完成后，Ollama 会在本机启动一个服务，默认 API 地址是：

```text
http://127.0.0.1:11434
```

### 2. 为 1060 选择合适的模型

在 **PowerShell 或 CMD** 中执行，例如：

```powershell
ollama pull qwen2.5-coder:7b
```

其他可选（示例）：

- `ollama pull qwen2.5:7b`
- `ollama pull deepseek-coder-v2:7b`

原则：

- 尽量选择名字里带 `7b`、`coder` / `instruct` 的模型
- 如果有 `q4` / `4bit` 等量化版本，优先选这些，更省显存

拉取完成后，先在本地测试一下：

```powershell
ollama run qwen2.5-coder:7b
```

如果能正常回答问题，说明本地模型就绪。

### 3. 在 OpenClaw 中接入 Ollama 本地模型

OpenClaw 的具体配置文件路径可能略有差异，这里给一个**示意结构**（以 JSON 为例，重点是思路）：

```json
{
  "models": {
    "providers": {
      "ollama": {
        "apiBase": "http://127.0.0.1:11434/v1",
        "apiKey": "local-ollama" 
      }
    },
    "defaults": {
      "chat": {
        "provider": "ollama",
        "model": "qwen2.5-coder:7b",
        "contextWindow": 8192,
        "maxTokens": 1024
      }
    },
    "mode": "merge"
  }
}
```

说明：

- `apiBase`：指向 Ollama 的 OpenAI 兼容接口（很多教程会用 `/v1`，按官方文档为准）
- `apiKey`：本地部署时通常不会真的校验，你可以填一个占位字符串
- `model`：要和你在 `ollama pull` 里用的模型名字一致
- `contextWindow` / `maxTokens`：可以按显存情况适当调小，避免 OOM
- `mode: "merge"`：表示允许和其他云模型“混用”，本地不够用时可以让云模型兜底

实际编辑配置时，建议参考官方文档当前推荐格式，把上面这些关键字段“迁移”进去即可。

### 4. 备用方案：LM Studio

如果你更喜欢图形界面，也可以用 **LM Studio**：

1. 在官网下载安装 LM Studio（Windows 版）
2. 在应用内搜索并下载一个 7B 级别的模型（同样建议选择 Qwen/DeepSeek 一类）
3. 在 LM Studio 里开启本地服务器（默认端口往往是 `1234` 或类似）
4. 在 OpenClaw 配置中，将 `apiBase` 改为 LM Studio 提供的地址，例如：

```json
"apiBase": "http://127.0.0.1:1234/v1"
```

其他配置思路与 Ollama 类似。

## 一步一步的安装攻略（从零开始）

以你的情况（Windows + GTX 1060）为例，可以照着这份清单来：

1. **准备环境（一次性）**
   - 更新 NVIDIA 显卡驱动（从 NVIDIA 官网下载最新驱动并安装）
   - 确保系统有 ≥16GB 内存，磁盘空余 ≥30GB
   - 在 PowerShell 中执行一次：
     - `Get-ExecutionPolicy`
     - 如为 `Restricted`，执行：`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`
2. **安装本地推理引擎**
   - 访问 `https://ollama.com/` 下载并安装 Windows 版 Ollama
   - 打开终端执行：`ollama pull qwen2.5-coder:7b`（或其他 7B 模型）
   - 用 `ollama run qwen2.5-coder:7b` 简单对话，确认模型能跑起来
3. **安装 OpenClaw**
   - 以管理员身份打开 PowerShell，执行：
     - `iwr -useb https://openclaw.ai/install.ps1 | iex`
   - 完成后运行：`openclaw onboard`，按引导完成初始配置
   - 运行：`openclaw dashboard`，确认控制台能正常打开
4. **让 OpenClaw 用上本地模型**
   - 打开 OpenClaw 的配置文件（参考官方文档中的路径说明）
   - 按前文示例添加 `ollama` provider，并把默认聊天模型指向 `qwen2.5-coder:7b`
   - 保存配置后重启 OpenClaw 服务（根据安装方式可能需要运行相应命令，或重启电脑）
5. **验证**
   - 执行：`openclaw doctor`，确认各项检查通过（有少量 Warning 一般问题不大）
   - 在 dashboard 或 CLI 中发起一次对话，观察是否在本地 GPU 上跑（可以通过显卡监视工具查看）

日常使用时，你只需要：

1. 确保 Ollama / LM Studio 已经启动（本地模型服务在线）
2. 启动或确认 OpenClaw 服务在运行
3. 通过 Web 面板 / CLI / 其他集成入口与“龙虾”对话即可。

## 与飞书集成（可选）

如果你日常工作在飞书（Feishu）里，可以把 OpenClaw 接成一个**飞书机器人**，让“龙虾”在飞书里陪你写文档、拉群里讨论、自动处理日常事务。

> 提示：飞书集成目前对版本和权限有一定要求，具体细节请以官方文档为准，这里给出一条适合个人/小团队的典型路径。

### 1. 在飞书开放平台创建应用

大致步骤（只需做一次）：

1. 访问飞书开放平台：`https://open.feishu.cn/app`
2. 创建一个 **企业自建应用**
3. 记录下：
   - App ID
   - App Secret
4. 在“权限管理”里为应用添加常用权限（可以按官方提供的 JSON 模板批量导入），例如：
   - 发送/接收消息
   - 读取/编辑云文档
   - 管理日历、日程、任务等（按自己实际需要勾选）
5. 在“机器人”能力中启用机器人，并在“事件订阅”里选择 **长连接（WebSocket）模式**。

完成以上步骤后，飞书侧的应用就准备好了。

### 2. 在 OpenClaw 中安装飞书插件

在 **Windows PowerShell** 中执行（确保 OpenClaw 已安装）：

```powershell
# 安装飞书插件
openclaw plugins install @openclaw/feishu
```

安装完成后，通过向导添加飞书渠道：

```powershell
# 向导方式添加渠道（包含飞书在内的多种渠道）
openclaw channels add

# 或者在初始引导中一并配置
openclaw onboard
```

向导会询问你：

- 飞书的 App ID / App Secret
- 要启用的消息模式（长连接）
- 哪些人 / 群可以使用机器人（白名单 / 黑名单策略）

把在飞书开放平台拿到的 App ID / Secret 按提示填进去即可。

### 3. 启动网关并完成配对

在 PowerShell 中执行：

```powershell
# 启动 OpenClaw 网关（Gateway），用于接收/发送飞书消息
openclaw gateway

# 实时查看日志（可选）
openclaw logs --follow
```

接着：

1. 在飞书客户端中，找到你刚创建的机器人，给它发送一条消息（例如“你好”）。
2. 在 OpenClaw 的日志或控制台中，会看到一个 **配对码（pairing code）**。
3. 在 PowerShell 中执行：

```powershell
openclaw pairing approve feishu <这里替换成配对码>
```

看到“配对成功”之后，这个飞书账号 / 群就被正式授权给你的 OpenClaw 实例了。

从此以后，你就可以：

- 在飞书的私聊窗口直接和“龙虾”对话（背后走的是你配置好的本地模型 + 云模型）
- 在群聊中 @ 机器人，让它帮忙总结聊天记录、写会议纪要、生成代码片段等等

### 4. Windows + WSL + 飞书 的推荐组合

结合你当前环境，一个比较稳妥的架构是：

- **Windows**：运行 OpenClaw（养龙虾）、Ollama（本地模型）、飞书插件  
- **WSL**：运行具体的后端服务 / 脚本（例如 Python、Node 项目）  
- **飞书**：作为日常入口（手机/电脑都能用），把日常工作流都接进来

WSL 里的代码如果需要调用 OpenClaw 或 Ollama，只需要通过 HTTP 访问宿主机的地址（例如 `http://127.0.0.1:11434` 或 OpenClaw 提供的 API 地址）即可，这部分可以在你后续具体项目里按需接入。

## 硬件方案与云/本地选择

很多人聊“养龙虾”，会提到 **Mac mini**、**Windows + 独显主机**、或者**纯云端大模型**。这里结合常见疑问简单梳理一下。

### 1. 为什么很多人用 Mac mini？

常见原因主要有三点：

- **功耗 + 噪音友好**：Mac mini（尤其是 M 系列）待机和满载功耗都比较低，几乎没什么风扇噪音，很适合 7x24 小时当“小服务器”放在桌上或客厅。
- **稳定、维护简单**：不需要自己折腾太多驱动和系统配置，对非重度折腾党更友好。
- **“云端为主”的典型用法**：很多人用 Mac mini 跑 OpenClaw / 其它 Agent，其实**主要还是走云端模型**（OpenAI、Claude、国内云厂商），本地只做“调度和自动化中枢”，不一定在本机强跑大模型。

> 关键点：**Mac mini 是集成 GPU（Apple Silicon 的统一内存架构），没有传统意义的独立显卡插槽**。它当然也可以跑一些本地模型，但受限于显存大小和生态，目前更适合“轻本地 + 云端为主”的架构。

### 2. Mac mini 有显卡吗？

- 从硬件形态上看，它没有像台式机那样的 **独立显卡插槽**。
- M 系列 Mac 的“GPU”集成在同一颗 SoC 上，走的是统一内存（比如 16GB / 24GB / 32GB 共享给 CPU + GPU）。
- 这类 GPU 在一些本地模型框架里也能用（如 ollama / llama.cpp 的 Metal 加速），但：
  - **显存 = 系统内存的一部分**，抢内存很凶；
  - 对于极大模型（几十 B 参数），依然吃力。

一句话总结：**Mac mini 有 GPU 能力，但不是传统可更换的独显卡，更适合轻量本地 + 云端为主的玩法**。

### 3. Windows + 独立显卡是不是更好？

这要看你的目标：

- 如果你想尽可能 **多跑一点本地模型**、玩不同模型的细节调优：
  - Windows + NVIDIA 独显（哪怕是 1060）在生态和工具上会更丰富，很多推理框架优先支持 CUDA。
  - 以后你也可以升级显卡（比如从 1060 升到 4070/4090），同一套系统还能继续用。
- 成本和体验上的取舍：
  - Windows + 独显台式机：**更吵、更耗电，但本地算力更灵活**。
  - Mac mini：**更安静、更省电、空间占用小，但本地算力上限有限**。

如果只看“养龙虾”这个用途，而且你已经有 **Windows + 1060**，通常：

- **没必要专门为了养龙虾去换 Mac mini**；
- 更划算的做法是：先把 Windows + 独显这套利用好，再视需要叠加云端模型。

### 4. 养龙虾用云端 AI tokens 还是本地大模型更好？

可以这样对比：

- **云端模型（按 token 计费）优点**：
  - 算力强、效果好，尤其是最新一代 GPT、Claude、Qwen-Max 等
  - 不用操心显卡、显存、部署细节
  - 上下文长度和多模态能力往往比本地方案强
- **云端模型缺点**：
  - 有费用（按 token 计费）
  - 有网络依赖和延迟
  - 需要考虑数据隐私和合规

- **本地大模型优点**：
  - **零 token 成本**，长期使用成本可控
  - 数据只在你自己的机器上流转，隐私更可控
  - 可以离线工作（断网也能用）
- **本地大模型缺点**：
  - 受限于硬件（显存、内存、磁盘）
  - 模型效果相对云端旗舰往往差一截
  - 部署和维护成本更高

所以更现实的选择是：**混合模式**——这也是 OpenClaw 推荐的默认架构：

> 日常任务、本地代码、隐私较强的数据 → 本地 7B/8B 模型；  
> 需要高质量写作、超长上下文、大型推理任务 → 云端旗舰模型。

在配置层面，就是前面示例里的：

- 同时配置本地 provider（如 `ollama`）和云端 provider（如 openai/claude 等）
- 把 `models.mode` 设为 `"merge"`，让 OpenClaw 根据任务类型或你的指令选择合适后端。

### 5. Mac mini 上一般怎么“养龙虾”？

大多数 Mac mini 用户的典型架构是：

- 在 Mac mini 上长期运行 OpenClaw / 其它 Agent，当作一个常驻“AI 中枢”
- **模型以云端为主**：
  - OpenAI、Claude、国内云 API 等
  - 有时搭配一个 7B 左右的本地模型做轻量任务或兜底
- Mac mini 的集成 GPU 也可以跑本地模型（通过 Metal 加速），但更多是：
  - 跑 7B 左右的模型
  - 把特别复杂、对效果要求很高的任务交给云端模型

而你现在这台 **Windows + 1060**，更适合：

- 在 Ollama 上长期挂一个 7B 量级模型做“本地常驻大脑”
- 再按需接入云端模型兜底

从性价比角度看，这对个人开发者/独立工程师已经是一套非常不错的“养龙虾”配置了。

### 6. “经常不开机/关机 + 电费”怎么考虑？

**OpenClaw 并不强制你 7x24 开机。**  
只是如果你希望它像“家里的小服务器”一样随叫随到，就需要尽量保持主机常开（或者至少白天开机、夜间睡眠）。

- 一台典型的 **Windows + GTX 1060 台式机**：
  - 待机/轻负载功耗大约在 **80–120W** 之间（整机，不是显卡单独）
  - 取中间值按 **100W（0.1kW）** 估算
- 若 7x24 小时常开一整年：
  - 年耗电量 ≈ 0.1 kW × 24 h × 365 ≈ **876 kWh**
  - 以居民电价 **0.6–0.8 元/kWh** 估算：
    - 年电费 ≈ 876 × 0.6–0.8 ≈ **525–700 元/年**

如果你晚上关机、周末关机，或让电脑自动休眠，实际电费一般会再打个 **5–7 折**，粗略可以认为：

> **个人常驻“养龙虾”主机的电费数量级：一年大概 300–700 元人民币。**

你可以根据自己使用习惯（全天开机 vs 白天开机）在这个区间内做预估。

---

### 7. 云端模型 token 费用的大致量级

不同模型、不同厂商价格差异很大，这里以一个“工程师日常用得上、价格又比较亲民”的档位举例，例如 **OpenAI GPT-4.1 Mini / 类似价位模型**（2026 年大致价格）：

- 参考价格（按美元，1 美元 ≈ 7.2 元人民币）：  
  - 输入：约 **$0.40 / 1M tokens** → 约 **2.9 元 / 100 万 tokens**  
  - 输出：约 **$1.60 / 1M tokens** → 约 **11.5 元 / 100 万 tokens**
- 混合一下，粗略按 **10–15 元 / 100 万 tokens（输入+输出综合）** 估个中间价。

如果一个工程师日常比较重度使用：

- 假设每天总共用掉 **300 万 tokens**（含询问、写代码、重构、文档等）：
  - 每天费用 ≈ 3 × 10–15 元 ≈ **30–45 元/天**（这是非常“烧”的用法）
- 更现实一点的中等使用量：**50–100 万 tokens/天**：
  - 每天 ≈ 5–15 元
  - 一年（按 250–300 个工作日）≈ **1,000–3,000 元/年**

很多人会同时搭配一些更便宜的国内模型、批处理接口等，实际均摊价格往往 **更低**。  
因此可以给出一个比较保守、适用于多数工程师的估计：

> **如果主要用云端模型做日常开发，token 成本的合理数量级是：一年大约 1,000–3,000 元人民币。**  
> 轻度使用可能只有几百块，极重度使用（大量自动化、长上下文分析）也可能上到 5,000+。

结合前面的电费估算，你可以粗略认为：

- **本地机器（电费）+ 云端 token 加起来，一年几乎肯定在 1,000–4,000 元这个数量级**  
- 对于提升开发效率、自动化程度明显的场景，这个投入通常是值得的。

## 常见问题与限制

- **Q：1060 显存太小，会不会很卡？**  
  A：相比云端大模型肯定慢一些，建议从 7B 量化模型开始，先追求“能跑、稳定”，再考虑速度。

- **Q：本地跑不动大模型怎么办？**  
  A：可以采用“混合模式”：日常用本地 7B 做大部分工作，把关键、超长上下文的任务交给云端模型（在 OpenClaw 配置中保留云端 provider 即可）。

- **Q：一定要用 Ollama 吗？**  
  A：不一定。只要是提供 OpenAI 兼容 API 的本地引擎（LM Studio、vLLM 等），都可以参考类似配置方式接入。

- **Q：和 Cursor、Claude Code 怎么配合？**  
  A：可以把 OpenClaw 当作“后台总控”，用于长期任务、自动化；把 Cursor/Claude Code 当作“日常写码 IDE 助手”。三者并不冲突。
